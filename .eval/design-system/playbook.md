# Design system playbook

This is a bookmarking product whose UI spans a browser extension, a mobile app, a landing site and a documentation site. The extracted tokens come from four sources: a Docusaurus docs theme (Infima variables for alert, code, navbar, menu, TOC and primary color scales, plus transition timings), a shared Tailwind globals sheet (semantic background/foreground, card, popover, primary, secondary, muted, accent, destructive, border, input, ring and radius), a mobile Tailwind config mirroring those semantic color roles with a hairline border width, and a landing Tailwind config defining a display font family. The annotated components all belong to the browser extension, which lets a user sign in against a configured server address, save the current page as a bookmark, edit its title and note, assign lists and tags, confirm saves and deletions, and adjust settings; a small set of shadcn-style primitives (badge, button, command palette, dialog) underpins those screens.

## In one screen

- **Theme lives in:** a Tailwind config file.
- **Tokens:** 87 in 10 group(s), folded from 201 declaration(s).
- **Themes:** light and dark.
- **Spent:** 56 token(s) are used somewhere; 31 are declared and never used.
- **Components:** 809 declared, 131 primitives, 41 with variants (164 variant value(s)).
- **Disagreements:** 1235 instance(s) in 6 kind(s). See the last section.

## Provenance

The primitives are generated by shadcn/ui: `apps/web/components.json` declares style `default`, base colour `slate`, icon library `lucide`, primitives at `unstated`, and CSS variables on. A reader who knows that convention knows most of this system before reading any of it.
